# GRACE Downloader — 构建与打包指南

本文说明如何从本仓库源码构建 **v1.0.1 发布版**（PyInstaller 独立程序 + Inno Setup 安装程序）。

> 发布版源码 = [`src/grace_downloader_gui_release.py`](../src/grace_downloader_gui_release.py)，
> 与 Releases 里 `GRACE_Downloader_Setup_v1.0.1.exe` 内的代码一一对应（GPL v3 要求）。

---

## 1. 目录约定

```
GRACE-Downloader/
├── src/
│   ├── grace_downloader_gui_release.py   # 程序源码（PyInstaller 的入口脚本）
│   ├── grace_downloader_release.spec     # PyInstaller 配置
│   ├── installer_release.iss             # Inno Setup 安装脚本
│   ├── make_help_html.py                 # 生成随包分发的 使用说明.html（无需 GUI）
│   ├── build_release.bat                 # 一键构建（在本目录内运行）
│   └── grace_icon.ico / grace_icon_preview.png
└── docs/
    ├── screenshots/*.png                 # 界面截图，打包时会被暂存进 src/help_docs
    └── 地球重力与人类生活TVGG.jpg          # 公众号二维码，打包时暂存到 src/
```

`src/build_release.bat` 会自动把 `docs/` 里的图片暂存到 `src/` 下（`help_docs\` 与二维码），
再调用 PyInstaller；产物输出到仓库根目录的 `dist\`。

> **注意**：`.bat` 必须是 **CRLF** 行尾。用 LF 行尾保存的批处理会让 `cmd` 逐行解析错乱，
> 症状是脚本输出一堆 “'xxx' is not recognized as an internal or external command”，
> 而且可能在错误的目录里执行到后面的步骤。

## 2. 环境准备

**不要**在装了 numpy / pandas / scipy 的大环境里打包，否则体积会从约 124 MB 膨胀到 400 MB+。
建议建一个专用精简环境：

```bat
conda create -n grace -y --no-default-packages python=3.13 pip
%USERPROFILE%\anaconda3\envs\grace\python.exe -m pip install earthaccess PyQt5 pyinstaller
```

只用三个包：`earthaccess`（含 fsspec / s3fs / requests 等依赖）、`PyQt5`、`pyinstaller`。

环境变量 `GRACE_PYTHON` 可覆盖脚本使用的解释器：

```bat
set GRACE_PYTHON=C:\path\to\python.exe
```

## 3. 一键构建

```bat
src\build_release.bat
```

脚本依次做四件事：

| 步骤 | 内容 |
|---|---|
| 1/4 | 把 `docs\screenshots\*.png` 与二维码暂存到 `src\`（spec 需要它们在场） |
| 2/4 | PyInstaller 打包 → `dist\GRACE_Downloader_v1.0.1\` |
| 3/4 | 把说明书、`LICENSE`、`许可说明.md`、第三方声明与源码复制到便携版目录，并用 `make_help_html.py` 生成随包的 `使用说明.html` |
| 4/4 | 若装了 Inno Setup，编译安装程序 → `dist\GRACE_Downloader_Setup_v1.0.1.exe` |

**产物**

| 产物 | 路径 |
|---|---|
| 便携版目录 | `dist\GRACE_Downloader_v1.0.1\`（双击 `GRACE_Downloader.exe` 即可运行） |
| 安装程序 | `dist\GRACE_Downloader_Setup_v1.0.1.exe` |

### 分步执行（等价）

```bat
cd src
%USERPROFILE%\anaconda3\envs\grace\python.exe -m PyInstaller --clean --noconfirm ^
    --distpath ..\dist --workpath ..\build_release grace_downloader_release.spec

:: 复制文档与许可（见 build_release.bat 第 [3/4] 步）
:: 再编译安装程序：
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer_release.iss
```

## 4. spec 里的两个关键点

### 4.1 必须显式收集 OpenSSL 动态库

conda 的 `libssl-3-x64.dll` / `libcrypto-3-x64.dll` 不在任何包目录里，而在 `<env>\Library\bin`，
PyInstaller 的钩子找不到它们；结果就是打包后的程序 `import ssl` 直接失败，
连带 `earthaccess` / `requests` 全部不可用（报 `DLL load failed while importing _ssl`）。
`grace_downloader_release.spec` 因此显式收集这两个 DLL（约 8.4 MB）。

### 4.2 不要对云依赖用 `collect_all()`

`s3fs / botocore / aiobotocore / requests / certifi` 一旦 `collect_all()`，依赖树会被当作
数据文件铺开，铺开的 `urllib3` 会盖掉正确冻结的副本，导致
`from urllib3.util.ssl_ import ssl` 在打包程序里失败。PyInstaller 自身的分析已经够用。

同时对 `numba / llvmlite / rasterio / GDAL / scipy / pandas / xarray` 等传递依赖加了
`excludes`，包体因此保持在约 124 MB。

## 5. 安装程序（Inno Setup）

- 安装 Inno Setup 6/7：`winget install JRSoftware.InnoSetup`
- `installer_release.iss` 使用 `PrivilegesRequired=lowest`，**默认按用户安装、不弹管理员**
- 输出：`dist\GRACE_Downloader_Setup_v1.0.1.exe`
- 发新版本时记得改 `MyAppVersion` 并**重新生成 AppId GUID**（ISCC 菜单 Tools → Generate GUID）

## 6. 发布到 GitHub

1. 更新 `RELEASE_NOTES.md`（版本号、变更）
2. 构建得到 `dist\GRACE_Downloader_Setup_v1.0.1.exe`
3. 在仓库 Releases 里新建 tag（如 `v1.0.1`），上传安装程序
4. 在 Release 说明里贴上 SHA256，便于用户校验：

```powershell
Get-FileHash .\dist\GRACE_Downloader_Setup_v1.0.1.exe -Algorithm SHA256
```

## 7. 常见问题

**Q: 打包后 exe 为什么 120 MB 以上？**
A: 里面是完整的 Python 解释器 + PyQt5 + earthaccess 及其依赖，属正常结果。

**Q: 界面截图是空白框？**
A: 截图必须在**真实 Windows 会话**下渲染。无字体的离屏渲染（`QT_QPA_PLATFORM=offscreen`）
会得到空框。本仓库的截图是预先做好并随包分发的；程序在缺少截图时也会自行重新截图。

**Q: 杀毒软件报毒？**
A: PyInstaller 引导程序偶发误报，属于行业常见现象；可在防护历史里恢复或加白名单。
